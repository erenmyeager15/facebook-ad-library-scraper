## Evidence

Owner Insights showed one failed customer run on October 6 on build 1.0.31. Its
log is not shared, so that exact failure remains unattributed.

Owner diagnostic `9WaW2dtBZfRkaqrDO` (1.0.31, Nike/US, 5 ads, Residential):
the first three navigations failed with `net::ERR_CERT_COMMON_NAME_INVALID` and
only the fourth (last allowed) attempt succeeded. One more failure would have
produced a FAILED run with zero ads. Crawlee's `ROTATE_PROXY_ERRORS` list does not
include certificate or most Chromium `net::ERR_*` errors, so the same bad
residential exit was reused across retries.

## Change

`isBadExitError()` in `src/navigation.ts` matches proxy-side network/TLS failures
(cert, SSL, connection, tunnel, proxy and navigation timeouts). The crawler's
`errorHandler` retires the session on those errors, so each retry gets a fresh
browser and proxy exit. Facebook block, scope and content errors are unchanged.
98/98 unit tests pass.
