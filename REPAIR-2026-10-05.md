## Further DOM media repair

A read-only check of the public ad and matching Nike search confirmed that
baseline ad `925321173274919` still has a video, including public video source
and poster attributes. A new intercepted browser fixture reproduces another
loss path: when the video binary request is blocked, a player error handler can
remove the video element and replace it with an image before extraction.

`src/dom-media.ts` installs a bounded observer before navigation. It remembers
public video source/poster attributes under the nearest unambiguous Library ID
and makes no data requests. The router may use these fields only to enrich
already-observed matching ads. Exact search-scope checks prevent reusing media
after a query/filter change. The cache retains at most 500 ad entries and admits
later pagination; unsupported or oversized URLs are discarded. Aggregate counts
are logged for live diagnosis without logging media URLs.

The new offline negative control saves an image-only row after player removal;
the repaired case saves the same ad with video URL and thumbnail. Both download
zero video files. Scope changes, ambiguous IDs, unsafe/oversized URLs, source
child elements and 510 mounted video cards with bounded retention also pass.
All 96 unit tests and the TypeScript build pass. This reproduction supports the
repair mechanism but does not prove the exact cause of every cloud omission.

## Changes

- Replaced the document-wide image gate with shared discovery of actual ad card
  roots. Unrelated images no longer reject a valid search.
- Preview readiness examines at most 25 new candidates per batch. It activates
  only their lazy images, treats failed images as incomplete, and requires a
  stable media-shape settling window before extraction to allow delayed hydration.
- Extraction consumes the exact checked candidate IDs, so a rejected prefix
  cannot cause later video cards to be saved before their preview is ready.
- Complete structured creative metadata bypasses DOM preview loading. Sparse
  snapshots and incomplete declared videos fall through to same-ID DOM media
  recovery while retaining structured text, dates, links and other source fields.
- Pending cards are withheld without consuming result fees. Ready siblings are
  saved, and unresolved previews remain explicit `limited/preview_unready`
  coverage. Zero usable ads with unresolved previews stays retryable; it is never
  reported as confirmed empty.
- Bounded DOM scans advance past inspected rejects and duplicates, and drain
  already-loaded batches before another scroll/network wait. Later cards are
  reachable beyond the former first-250-root limit.

Price configuration, memory default, search filters, result/spending limits,
single-page concurrency and atomic save/charge behavior were not edited. The
existing `.actor/actor.json` has stale startup pricing; a release must merge only
approved source changes into the current remote version, preserving live pricing
and default settings rather than blindly pushing that manifest.
